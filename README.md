# 灵绘工坊

`astrbot_plugin_linghui_studio` 是 AstrBot 的文生图、图生图与图像工作流插件。它保留了上游手办化插件的完整功能集，并补充了受控群白名单、独立无限额度名单、多渠道自动回退、提示词翻译/优化和可视化 Dashboard。

插件使用独立的插件 ID、数据目录、Web API 路径和 LLM 工具名。聊天命令默认是短命令；当需要与其他绘图插件共存时，可以在 Dashboard 设置命名空间并关闭短命令，以避免命令冲突。

## 适用版本

- AstrBot `>= 4.16, < 5`
- Python 依赖：`aiohttp`、`Pillow`、`PyMuPDF`
- QQ 头像参考图需要当前平台能提供发送者或被艾特用户的 QQ 数字账号。

## 安装

在 AstrBot Dashboard 的插件页使用仓库地址安装，或将本目录放入 AstrBot 插件目录后重载：

```text
https://github.com/Whereis-Alice/astrbot_plugin_linghui_studio
```

首次使用请在“灵绘工坊”插件页面完成三项配置：

1. 在“绘图渠道”添加至少一个渠道，填写接口模式、地址、API Key 和模型。
2. 在“权限与额度”将可使用的群加入“允许生图的群白名单”。
3. 为用户或群发放额度，或将其加入对应的无限次数名单；默认个人额度开关是开启的。

默认群聊访问模式为白名单。此模式下未加入 `group_whitelist` 的群不会发起生图请求；白名单留空就表示所有群聊都不能生图。

## 命令模式

以下示例假设 AstrBot 的命令前缀为 `#`。

默认不需要“灵绘”前缀：

```text
#文生图 雨后的霓虹街道，一只穿雨衣的橘猫，电影感，16:9
#画 复古胶片人像，暖色自然光
#bnn 复古胶片人像，暖色自然光
#bnn @甲 @乙 两个人在雨后的霓虹街道合影
#手办化
#预设列表
```

`#画` 是可配置的自定义绘图子命令，默认值为“画”。它没有图片时执行文生图；携带图片、回复图片消息或明确引用上文图片时执行图生图。上游兼容指令 `#bnn` 始终保留，功能与 `#画` 相同；它还会把消息中被艾特用户的 QQ 头像按艾特顺序加入参考图，支持多人艾特、自动去重，并忽略机器人自身。当管理员改了 `extra_prefix` 时，`#bnn` 仍可继续使用。`#手办化` 等预设需要图片输入。

### 与其他绘图插件共存

在 Dashboard 的“运行设置”中：

1. 将“可选命令命名空间”设为例如 `绘图`。
2. 关闭“启用不带命名空间的直接命令”。

之后所有入口都使用命名空间加空格：

```text
#绘图 文生图 一只橘猫
#绘图 画 一只橘猫
#绘图 bnn 一只橘猫
#绘图 手办化
#绘图 通道 primary
#绘图 lm列表
```

命名空间模式同时接受上游的预设、参考图和管理命令别名，例如 `lm列表`、`lma`、`lmref添加`、`图片转PDF`。插件 ID、配置数据、Web API 和 LLM 工具始终是独立的。

| 44 个默认预设 | 完整保留上游默认预设，可在 Dashboard 或聊天命令中增删改。 |

## 插件配置分区

AstrBot 的插件配置会保持原有键名，升级不会把已有设置迁移成嵌套对象。为避免长配置列表难以辨认，所有字段均以 `【模块】` 开头，并按下列顺序连续排列：

| 配置模块 | 包含内容 |
| --- | --- |
| `【命令与帮助】` | 命令前缀、命名空间、短命令开关、自定义绘图子命令和帮助文本。 |
| `【绘图渠道与回退】` | 多渠道列表、主渠道、带参考图优先渠道和回退顺序。 |
| `【兼容单接口】` | 未使用渠道列表时的旧式单接口地址、Key、模型、尺寸、超时和代理。 |
| `【绘图运行与排障】` | 模型回显、上游错误显示与并发抢占。 |
| `【访问权限】` / `【额度与签到】` | 群白名单和黑名单、用户访问控制、私聊开关、无限次数名单、额度与签到。 |
| `【提示词处理】` / `【提示词与预设】` | 翻译和优化模型、系统提示词、反向提示词、预设、参考图与预设安全限制。 |
| `【人设与参考图】` | 人设开关、描述、关键词、场景和默认场景提示词。 |
| `【智能工具与批量处理】` | LLM 工具、上下文限制、冷却时间和批量任务并发。 |
| `【Dashboard 与缓存】` | 成功记录保留期限和 Dashboard 外观主题。 |

## 绘图渠道与回退

Dashboard 的“绘图渠道”从上到下定义优先级。每条渠道可独立设置：

| 字段 | 用途 |
| --- | --- |
| 渠道 ID | 唯一标识，例如 `primary`、`backup_1`。仅允许字母、数字、下划线和连字符。 |
| 接口模式 | `openai_image`、`openai_chat`、`gemini_official`、`custom_endpoint`。 |
| 地址与 API Key | 渠道独立保存；多个 Key 可按行填写并轮询。 |
| 默认模型 | 图生图模型；可另填带参考图模型和文生图模型。 |
| 允许带参考图请求 | 关闭后该渠道仍可用于纯文生图，但人设拍照、QQ 头像图生图、预设参考图和普通图生图都会跳过它。 |
| 带参考图模型 | 可选；仅给人设拍照、QQ 头像图生图、预设参考图和普通图生图使用。留空时使用默认模型。 |
| 图生图上传格式 | 人设拍照、头像图生图和参考图请求的传输格式。`auto` 会为 `gpt-image-*` 使用 OpenAI 标准的 multipart 文件上传；其他旧中转保留 JSON 优先的兼容逻辑。 |
| 允许作为回退渠道 | 前方渠道失败时，是否继续尝试此渠道。 |

管理员可快速查看或切换主渠道：

```text
#通道
#通道 primary
#通道 自动
```

选择 `primary` 后，请求先走该渠道；发生错误时仍会继续尝试后续允许回退的渠道。没有配置渠道列表时，插件会兼容旧式单接口字段。

> 保存说明：AstrBot 原生“插件配置”页和灵绘 Dashboard 保存的渠道选择都会写入同一份插件配置。原生配置页保存的新值会优先于旧版动态备份；若运行环境暂时无法写入原生配置，灵绘会保留本地兜底，并在下一次加载时只在原生值没有后续变化时恢复它。主渠道留空即恢复“自动”，带参考图优先渠道留空即恢复“跟随主渠道”。填写时必须使用已配置渠道的 `ID`，不是显示名称。

### 带参考图专用路由

“人设拍照”不是普通的文生图：只要加载了人设图，它就属于带参考图请求。QQ 头像图生图、带图的 `#画`/`#bnn`、带预设参考图的预设也走同一类路径。许多中转站只实现了文生图，或把图片编辑端点单独限流，所以“手办化能用”并不能证明人设拍照的上游也可用。

在 Dashboard 的“绘图渠道”页可单独设置“带参考图优先渠道”：

1. 为实际支持图片编辑或多模态参考图的渠道打开“允许带参考图请求”。
2. 在该渠道填写“带参考图模型”；不填则继承默认模型。
3. 在页面顶部的“带参考图优先渠道”选择它。留空则跟随当前主渠道。
4. 将只支持纯文生图的渠道关闭“允许带参考图请求”。

带参考图优先渠道失败后，会依次尝试其余已启用、允许回退且允许带参考图请求的渠道。插件不会悄悄丢掉人设图改成纯文生图，否则看似成功却无法保持人设身份。

### New API / GPT Image 配置

对于遵循 New API/OpenAI Images 协议的服务，建议在 Dashboard 新建或编辑渠道时这样填写：

| 字段 | 建议值 |
| --- | --- |
| 接口模式 | `openai_image` |
| 接口地址 | 只填站点基础地址，例如 `https://example.com`，不要填 `/v1/images`、`/v1/images/generations` 或 `/v1/images/edits`。 |
| 图生图/默认模型 | 支持编辑参考图的模型，例如服务端提供的 `gpt-image-*`。 |
| 带参考图模型 | 可选；建议明确填入服务商宣称支持 `/v1/images/edits` 或参考图输入的模型。 |
| 文生图模型 | 可选；需要把纯文生图与人设拍照分开时填写。`#bnn` 和 `#文生图` 会优先使用它。 |
| 图生图上传格式 | 保持 `auto`；`gpt-image-*` 会直接使用 `/v1/images/edits` 的 multipart 文件上传。 |

纯文生图使用 `/v1/images/generations`，带人设图、QQ 头像或其他参考图时使用 `/v1/images/edits`。两者不是同一个接口，不能把不带动作名的 `/v1/images` 当作完整请求地址。为兼容早期误填，插件会自动把 `custom_endpoint` 中形如 `/v1/images` 的地址按标准 Images API 处理；仍建议保存为上述配置，便于日后排障。

New API 的 OpenAI Images Edit 兼容接口只接受 `256x256`、`512x512` 或 `1024x1024`。因此，`gpt-image-*` 的带参考图请求会在后台自动使用 `1024x1024`，即使全局分辨率选了 2K 或 4K；`#bnn` 等纯文生图仍保留原来的分辨率选择。

已保存的人设图和预设参考图在提交给绘图渠道前会做格式兼容：PNG/JPEG 保持原样，WebP、GIF、BMP、TIFF 等会在内存中转换为 PNG 的首帧后再上传。原文件与 Dashboard 预览不会被改写。这样可以避免部分 OpenAI 兼容中转对 WebP 或动图参考图的文件上传处理异常。

## 权限、黑白名单与额度

访问控制和额度豁免是两件独立的事，优先级如下：

1. 用户黑名单、群黑名单优先拒绝。
2. 填写了用户白名单后，只有名单内用户可用。
3. 群聊白名单模式下，只有 `group_whitelist` 中的群可用。
4. 管理员额度豁免、用户无限次数、群无限次数只跳过额度扣除，不会跳过前三项。
5. 个人额度不足时，可选用群额度作为备用额度。

因此，将群号加入群白名单后，群成员可以生图，但仍会消耗额度。只有再加入“群无限次数名单”才会免额度。私聊默认关闭，可在 Dashboard 显式开启。

| 配置项 | 作用 | 关键规则 |
| --- | --- | --- |
| 允许生图的群白名单 | 在白名单模式下授予群聊生图资格 | 每项一个群号；名单外群不能生图，留空时所有群都不能生图；不会免额度。 |
| 禁止生图的群黑名单 | 无条件禁止指定群生图 | 每项一个群号；优先于群白名单、群无限次数名单和管理员额度豁免。 |
| 群无限次数名单 | 免除群内生图的额度扣除 | 不授予访问资格，群仍要先通过群聊访问模式和黑名单校验。 |
| 用户无限次数名单 | 免除指定用户的额度扣除 | 不绕过用户黑名单、用户白名单、私聊开关或群聊访问规则。 |

若将“群聊访问模式”改为 `all`，所有未被群黑名单禁止的群都可生图；此时群白名单不再限制群聊。管理员额度豁免也只影响扣费，不会改变访问权限。

签到可按固定次数或随机次数发放个人额度。Dashboard 支持查看、增加和重置用户/群额度。

## 提示词翻译与优化

在“提示词与预设”页可分别打开：

- “生成前翻译为英文”：保留原意、专有名词、比例与安全限制。
- “生成前优化提示词”：整理为更适合图像模型的表达。

两项同时开启时先翻译后优化。该模型使用独立的地址、API Key 和模型名；超时或失败时会记录日志并直接使用原始提示词，不会中断渠道回退。

## 自定义绘图反向提示词

Dashboard 的“提示词与预设”页提供“自定义绘图反向提示词”。填写后，它只会作用于 `#bnn` 和当前配置的自定义绘图指令（默认 `#画`），无论该请求是文生图还是携带参考图的图生图；留空即关闭。

绘图渠道之间没有统一的原生 `negative_prompt` 参数，因此插件会在翻译和优化完成后，以 `Negative prompt: ...` 的文本段追加到最终请求。这样主渠道和回退渠道都收到相同限制，也不会被提示词处理模型改写。建议填写模型更容易理解的英文短语，例如：

```text
lowres, blurry, watermark, text, malformed hands, extra fingers
```

它与“为预设追加安全限制”互相独立：后者仍只影响预设；这项配置不会影响预设、`#文生图`、头像图生图、人设拍照或 LLM 工具。

## QQ 头像参考图

推荐直接使用保留的 `#bnn` 指令。艾特一人时使用一张头像，艾特多人时会按艾特顺序提交所有头像：

```text
#bnn @甲 以这个头像为人物特征，复古胶片人像
#bnn @甲 @乙 两个人并肩合影，暖色自然光
```

重复艾特只会取一次，唤醒机器人时产生的机器人自身艾特不会被当成参考人物。只要取得至少一张头像，这次请求就按图生图处理，并使用“带参考图优先渠道”和对应的图生图模型。

旧指令仍保留：

```text
#头像图生图 复古胶片人像，暖色自然光
```

`#头像图生图` 只下载发送者自己的 QQ 头像并作为唯一参考图；在这个旧指令里艾特别人不会改变目标。当前平台不能提供 QQ 数字账号时，会提示改用 `#bnn @用户 <提示词>`，或直接发送参考图。

## 成功记录与缓存

从 v3.2.5 开始，每张成功返回给用户的图片都会在插件专属数据目录额外保存一份原图，并写入成功记录。Dashboard 的“成功记录”页可查看：

- 缩略图、原图下载、请求提示词、昵称与 QQ 号、群名称与群号、时间、任务类型、实际成功渠道、模型、预设、分辨率和文件大小。渠道回退成功时会显示最终成功的渠道；升级前缺少渠道信息的记录会明确显示“渠道未记录”。
- 缓存总量、今日成功数和保护数量；“概览”页还会在状态栏显示主渠道/备用渠道/模型，并按用户和群分别显示当天用量，底部展示最近 4 条成功图片。
- 收藏和锁定按钮。任意一个处于开启状态时，该图片及其提示词不会被自动清理；侧栏“收藏”可直接筛选已收藏的记录。

用户和群的 **QQ 号/群号始终是唯一身份**，用于访问控制、额度、签到和统计；昵称、群名称只用于管理员辨认。插件会在收到消息时更新最近一次见到的名称，新成功记录还会保存成功当时的名称快照。因此群友改昵称、群改名不会产生新的额度或统计条目。升级前已有的成功记录没有历史名称快照，会在 Dashboard 中尽量显示当前已知名称，缺失时只显示 ID。

默认保留期为 7 天，可在 Dashboard 的“运行设置”或 `generation_cache_retention_days` 配置项中调整为 1 至 365 天。插件启动时会立即检查一次，随后每 24 小时检查一次；超过保留期且未收藏、未锁定的记录会自动删除图片和提示词。页面中的“清理已过期”按钮执行同一规则。手动删除会删除指定记录，即使它已被收藏或锁定，因此页面会要求二次确认。

成功记录只从升级后新成功的请求开始累积，无法从旧的聊天消息或历史发送记录反向恢复。记录列表先只读取文字元数据；图片卡片进入可见区域后，Dashboard 才通过 AstrBot Plugin Page 的受鉴权请求取回对应的小型 JPEG 缩略图，且同一时间最多加载两张。完整提示词只在展开该记录时读取，缩略图、提示词、列表和收藏筛选都会在页面会话中复用短时缓存。这样记录和收藏页不会因为一次读取大量原图或长提示词而变慢；翻页和切换页签会短暂复用已加载的列表，点击“刷新”会立即读取最新记录。原图下载也通过受鉴权接口发送附件，原始缓存文件不会暴露为浏览器可直接访问的本地路径。

### QQ 发送回执超时

QQ 适配器偶尔会在图片已经出现在聊天窗口后，才因为等待 `sendMsg` 回执过久而抛出超时。`v3.3.2` 只对这类同时带有 QQ 发送标识和超时字样的异常停止重发，并保留本次任务的成功状态，避免重复图片和错误的失败回复。它不会把所有超时都当作成功：绘图渠道错误、普通消息发送失败及其他平台错误仍会照常显示并进入原有处理流程。

## LLM 工具与自动判断

启用 LLM 工具后，AstrBot 可以调用独立的 `linghui_*` 工具执行用户状态检查、文生图、图生图、智能任务判断、批量并发处理、PDF 打包和人设拍照。开启“LLM 智能判断”后，插件会结合会话上下文判断文生图或图生图，并在触发后沿用相同的权限、额度、提示词处理和渠道回退流程。

## 图生图记录与输入原图

从 v3.4.0 起，成功记录不只保存结果图。只要本次请求实际带入了图片，灵绘还会保存这次请求使用的输入原图，并将它们与结果图、提示词和元数据绑定在同一条记录中。这样管理员可以在 Dashboard 回看“这张图是拿什么图做出来的”，而不是只能看到最终结果。

以下入口均会被记录：带图片、回复图片或引用图片的 `#画` 与 `#bnn`，QQ 头像图生图，人设拍照，带预设参考图的请求，普通/批量图生图，以及 PDF 批量图生图。若一次请求传入多张图片，记录会保留全部输入图，并按实际提交给绘图渠道的顺序展示。

在 Dashboard 中：

- “成功记录”可筛选文生图、图生图或全部；侧栏的“图生图工作台”会直接进入图生图筛选。
- 展开图生图卡片的“输入原图”即可按需加载缩略预览；结果图和每张输入原图都可独立下载。缩略图不会替换真实缓存文件。
- 收藏或锁定会同时保护结果图、输入原图、提示词和缩略图；在保留期（默认 7 天）后的自动清理不会删除这些受保护素材。手动删除仍会删除整条记录的全部素材。
- 为保证列表打开速度，输入原图不会随历史列表一次性传输，而是在管理员展开对应卡片时才加载。

### 旧记录的处理原则

旧版本没有缓存用户上传图、回复/引用图或 QQ 头像，因此不能从日志中可靠还原这些历史输入原图。Dashboard 会明确显示“旧版记录未缓存输入原图”，不会把其他图片伪装成原图。

如果旧记录使用了人设图或预设参考图，页面可能展示当前配置中的参考图作为排查候选；每张候选都会标注“非本次历史原图”。当前配置可能已经被更换或删除，因此它只能帮助核对，不能作为历史证据。

## Dashboard

AstrBot 会自动发现 `pages/linghui-studio/`。页面包含：

- 绘图渠道、接口地址、默认/文生图/带参考图模型、Key 掩码、启用状态和回退顺序；可为带参考图请求单独指定优先渠道。
- 可选命名空间与直接命令开关。
- 群/用户黑白名单、无限次数名单、签到和额度调整/重置。
- 44 个默认预设及自定义预设的增删改。
- 预设参考图与人设参考图的上传、查看和删除。
- 人设名称、描述、风格、触发词、默认场景和场景提示词。
- 提示词翻译/优化开关、独立模型、系统提示词和超时。
- 成功图片缓存、请求提示词、用户/群/渠道/模型元数据、分页查看，以及收藏、锁定、手动删除和过期清理。文生图、图生图与收藏记录都可按具体群聊、仅私聊或具体 QQ 用户筛选；群聊和个人条件可以叠加。
- 默认使用深色玻璃霓虹界面；侧栏采用分组导航与紧凑控制条，主题菜单、连接状态、重载和半透明荧光渐变保存按钮不会挤占主要内容。可选深色、浅色、“爱丽丝”和独立设计的“黑客终端”主题；黑客终端使用直角布局、命令行导航、终端字体、扫描线与电路网络背景，并非只替换颜色。四套主题都会立即写入 `dashboard_theme` 插件配置，重新打开 Dashboard、更换浏览器或清除浏览器本地数据后仍会保持；切换主题不会提交尚未保存的渠道、密钥或表单修改。侧栏品牌标记使用随插件发布的本地像素头像，不依赖外链。

页面重新加载时不会回传完整 API Key，只显示掩码。留空保存会保留原 Key；勾选“清除已保存的 API Key”才会删除。

人设图和预设参考图会显示为页面内的受鉴权缩略图，原始文件只保存在 AstrBot 的插件数据目录。上传后会立即重新加载并显示预览；缩略图不会改写或压缩实际用于生图的原图。

## 排障

| 现象 | 处理方式 |
| --- | --- |
| 群不在白名单 | 在 Dashboard 的“允许生图的群白名单”加入群号。 |
| 群已授权但提示额度不足 | 白名单只授予使用权；增加额度、关闭额度限制，或加入群无限次数名单。 |
| 主渠道报错 | 检查主渠道地址、模型和 Key，并确认后续渠道已启用且允许回退。 |
| 图生图直接返回了输入头像/原图 | 这是渠道回显了请求参考图，或兼容响应中只留下了输入图，并不是真正成功。v3.5.2 起插件会对结果与每张输入图做同图检测；命中后拒绝发送和记录，并自动回退下一条可用渠道。若所有渠道都这样返回，请检查该渠道的图生图端点与模型。 |
| `#手办化` 能成功，但人设拍照/头像图生图报 `Images API Error 400/503` | `#手办化` 也是图生图，因此这证明至少有一条带参考图调用链可用，不能简单归因于“不支持图生图”。人设拍照还会附带已保存的人设图和更严格的人设提示词；先确认 Dashboard 中的“带参考图优先渠道”和“带参考图模型”，并查看日志是否出现“已将…参考图标准化为 PNG”。WebP、GIF 等已保存素材会自动以 PNG 提交，原文件不变。若仍在 `POST /v1/images/edits` 后收到 503，则是该渠道或其上游对这次编辑请求失败，插件会继续尝试符合条件的回退渠道。 |
| 没有触发命令 | 检查 AstrBot 命令前缀、`prefix` 配置，以及命名空间/直接命令开关。 |
| 提示词处理失败 | 检查独立提示词模型的地址、Key 和模型名；失败时应自动回退原提示词。 |
| QQ 头像图生图不可用 | 确认平台可提供 QQ 数字账号，或直接发送参考图。 |
| 人设图或参考图已上传但页面显示破图 | 升级到 v3.2.0 后重启插件并刷新 Dashboard。该版本不再让浏览器直连需要授权的图片接口，而是通过 AstrBot Plugin Page 的鉴权请求返回缩略预览。 |
| 成功记录页为空 | 该页面只收集 v3.2.5 起的新成功请求。确认请求实际成功且插件数据目录可写，然后重新打开“成功记录”页。 |
| `drawing_channels[0]` 缺少 `__template_key` | 这是 v3.1.1 及更早 Dashboard 保存渠道时遗漏的 AstrBot `template_list` 内部标识。升级到 v3.2.0 后重启插件会自动修复；若插件无法启动，请先从插件配置中删除出错渠道，再由灵绘 Dashboard 重新添加。 |

## 数据与许可

图生图输入原图仅保存在 AstrBot 为本插件分配的运行数据目录，并只通过已登录的 Dashboard 插件接口预览或下载；它们不会写入仓库。请根据群规、平台规则和适用法律设置合理的缓存保留期，并谨慎授予 Dashboard 管理权限。

运行数据保存在 AstrBot 为本插件分配的数据目录，包括额度、签到、预设、人设图片、参考图、成功图片缓存、成功记录和动态配置备份。API Key 与运行时图片不会提交到本仓库。
