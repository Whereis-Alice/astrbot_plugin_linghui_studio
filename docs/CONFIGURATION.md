# 配置指南

## 渠道与回退

在 Dashboard 的“绘图渠道”中添加渠道并设置优先级。每条渠道可以单独设置接口模式、地址、API Key、默认模型、文生图模型、带参考图模型、上传格式和是否允许回退。

- `auto`：按模型和请求类型选择优先协议，并在明确的协议不兼容时有限回退。
- `openai_image`：优先 Images API。
- `openai_chat`：优先 Chat Completions。
- `gemini_official`、`grok`、`agnes`、`novelai`、`jimeng`：使用对应原生协议。
- `custom_endpoint`：使用完整自定义地址，不跨协议回退。

OpenAI 兼容站点通常只填写站点基础地址，例如 `https://example.com`，不要把 `/v1/images` 写进基础地址。纯文生图走 generations，带参考图走 edits；具体能力取决于服务商模型。

主渠道的模型全部失败后，插件会按优先级尝试其他启用回退的渠道。连续失败的渠道会暂时冷却；可配置失败阈值、冷却时间、Key 重试次数以及是否遇到安全拒绝时继续回退。

### 优先级、模型与尺寸

`priority` 默认 0，数值越大越优先，同值按列表顺序。全局主渠道、会话渠道或本次明确指定的渠道优先于数值排序；备用渠道仍按优先级。`models` 按列表顺序尝试，去重后最多 32 个；带参考图/文生图专用模型非空时先尝试它，再尝试列表。列表为空时沿用原默认模型。单模型仍保留 Key 轮换，全部模型失败后再换渠道。通过指令或会话手动指定的模型不被模型列表替换。内容审核拒绝是否继续尝试由现有审核回退开关决定。

`image_resolution` 支持 1K、2K、4K，`image_aspect_ratio` 支持页面列出的常用比例。渠道设置留空时沿用全局设置和既有参考图比例识别；非空比例同时用于文生图与参考图请求。显式请求参数优先于提示词中的尺寸/比例，提示词优先于渠道默认值。

### 单渠道每日总额度

`daily_limit` 默认 -1（不限），0 表示该渠道暂停，正整数为本服务器所有会话共用的每日成功次数。渠道成功返回一张结果扣一次；模型/Key 重试和其他渠道回退不重复扣此次数，失败或取消退回。并发请求先持久化预占再调用上游，避免跨会话超额。批量逐张计算；豪华模式的一次最终成功结果计一次，其中多路请求可能产生更多上游费用，这个次数并非供应商账单金额。

北京时间每天 00:00 自动清零，按请求开始日记账；旧日跨午夜结束的失败不影响新日。额度用完临时跳过该渠道，不修改配置中的启用开关；下一日自动恢复，手动关闭的渠道不会自动打开。用量保存在插件数据目录 `channel_daily_quota.json`，重载和重启保留。进程异常退出时未完成的预占保守计为已用，避免放大额度；文件损坏或写入失败会停止调用。修改上限保留当天已用次数；保持渠道 ID 可保留计数，改 ID 会形成新的额度身份。

### 渠道迁移与测试

渠道页的“导出渠道”下载 `linghui_channels.json`，包含保存的渠道、主渠道选择和真实 API Key（包括继承的 Key），请妥善保管。点击“导入渠道”选择文件即可替换所有渠道及主渠道选择。导入不迁移用量，也不改变其他插件设置；未设置的全局默认模型/尺寸以目标服务器配置为准。格式或字段错误拒绝导入，保存失败回滚。设置页原有“导出脱敏配置”仍隐藏 Key。

用 `#bnn 渠道m 一只猫`（渠道 ID 为 `m`，“渠道”与 ID 紧挨着），也可用 `#bnn --渠道 primary 一只蓝色小猫` 或 `#bnn --channel=primary 一只蓝色小猫` 临时选择渠道。参数放在提示词前，使用 WebUI 的渠道 ID；命名空间模式可用 `#绘图 bnn 渠道m 一只猫` 或 `#绘图 bnn --渠道 primary 一只蓝色小猫`。该请求只尝试指定渠道内的模型和 Key，失败不切换其他渠道，不修改会话/全局配置，仍受个人、群、全局总次数和渠道日额度限制。不带参数仍沿用原有路由，艾特头像参考图能力保留。

## 权限与额度

### 群聊

- **允许生图的群白名单**：白名单模式下，只有名单中的群允许生图；留空表示没有群获得权限。
- **禁止生图的群黑名单**：黑名单优先级最高，命中的群始终禁止生图。
- **群无限次数名单**：只免除额度扣减，必须同时位于允许生图的群白名单中才有效。

### 用户与私聊

- 用户白名单/黑名单控制个人访问。
- 用户无限次数名单只免除额度扣减。
- 私聊是否允许使用由“允许私聊生图”控制；私聊额度按 QQ 用户 ID 计算。

管理员可用 `#加用户额度 <QQ号> <次数>` 或 `#加用户额度 @用户 <次数>` 补个人次数，用 `#加群额度 <群号> <次数>` 补群公共额度。个人余额在群聊与私聊之间共用；补额度不授予访问权限。管理员身份、查询和重置方式见[管理员命令](ADMIN_COMMANDS.md#用户与群额度)。


### 所有会话共享的总次数

`global_total_limit` 默认 `-1`（不限）；设为 `0` 暂停所有生图，正整数表示所有会话累计消耗次数的总上限。它不是每个会话分别获得一份额度，也不是各用户/群剩余余额相加；例如总上限为 100，群 A 用 30 次、群 B 用 20 次、私聊用 10 次，全局剩余就是 40 次。

管理员发送 `#总次数 100` 设置上限、`#增加总次数 50` 增加上限、`#总次数 不限` 关闭上限；`#总次数` 和 `#额度` 显示已用与剩余。命名空间模式也支持 `#绘图 总次数 100` 等写法。Dashboard 的“权限与额度”可编辑同一上限。

管理员、无限次数名单、关闭个人/群限制的会话同样受总上限约束。批量任务按计划生成的张数统一扣减，多张参考图合成一张结果只计一次；重试和渠道回退不重复扣减。被拒绝的请求不扣个人/群额度。单图生成失败/取消及批量策略跳过的未执行图片会按原退款路径恢复全局次数；已执行的批量失败保留原有计费行为。

升级后从 0 开始累计（包括不限期间），不追溯旧图片历史；日期变化、插件重载、程序重启都不清零。调整上限保留已用次数，降低到已用次数以下会阻止后续请求。签到或增加个人/群额度不会改变全局上限；计数保存在插件数据目录 `global_quota.json`，数据损坏或计数写入失败时停止新增生图以避免错误放行。

### 手动指令冷却

`command_cooldown_seconds` 只限制手动指令和预设指令，包括 `#画`、`#bnn`、`#文生图`、`#头像图生图`、`#人设拍照`。冷却键为 `(QQ 用户 ID, 群号)`：同一用户在不同群互不影响，私聊单独计时。LLM 工具使用另一套 `llm_cooldown_seconds`，两者互不干扰；设置为 `0` 关闭。

## 提示词与预设

可分别开启提示词优化和翻译，并为两个模型设置独立地址、模型和系统提示词。处理失败时默认回退原提示词。

自定义反向提示词只追加到自定义绘图流程；预设安全限制可以单独配置。预设支持新增、修改、删除、示例图和多张参考图。

## 人设与每日状态

上传人设参考图后，可配置角色名称、描述、触发关键词、场景提示词、真人/动漫形象类型，以及每天稳定的穿搭、心情和时间段状态。人设拍照会使用这些信息并调用 AstrBot 当前人格完成自然收尾。

## 缓存与任务

成功记录会保存结果原图；图生图还会保存实际输入原图和提示词。记录可下载、收藏或锁定。自动清理只删除过期且未收藏、未锁定的记录；“清空未收藏”会立即删除所有未受保护记录。

批量任务支持立即停止、跳过继续、跳过但限次三种失败策略。后台模式提交任务后即可继续聊天，完成后插件主动发回图片。
