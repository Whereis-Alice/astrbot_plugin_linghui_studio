# 排障手册

## QQ 图片发送慢或提示“图片已过期”

成功文案中的耗时是生成耗时，QQ 上传和发送回执可能还需等待。查看日志中的 `Linghui QQ delivery copy` 和 `Linghui image delivery`，可分别看到原始/发送体积、排队、图片处理和发送耗时。

默认大图会使用高质量发送副本降低上传量，并按机器人逐张发送。WebUI 设置页可以调整目标大小、最长边、JPEG 质量和同时发送数，也可以切换为发送原图。下载原图仍使用完整缓存。

“已过期”不能单凭文件大小判断。插件发送的是下载后的图片字节；若原图缓存完整、OneBot 图片 URL 也能下载，但 QQ 客户端仍打不开，应继续检查 QQ 客户端与协议端的图片资源、上传日志和网络。压缩可降低上传压力，不能保证修复协议端资源异常。平台回执较慢时请先等候，避免立即重发产生重复图片。

## 命令没有反应

确认消息使用了 AstrBot 顶层唤醒词，或直接 @机器人。若启用了命名空间，请使用“命名空间 + 命令”，例如 `#绘图 bnn 一只猫`。插件的 `extra_prefix` 只影响自定义绘图别名，不会绕过 AstrBot 的唤醒规则。

`/` 不是必需前缀，实际前缀取自当前会话的 AstrBot 配置。私聊默认可以直接发命令；若私聊也必须加前缀，请检查 AstrBot 的“私聊需要唤醒词”设置。

## 400、503 或渠道均失败

- 503、超时通常是渠道或上游服务暂时不可用，可使用 `#通道` 切换会话渠道验证。
- 400 可能是模型、尺寸、请求格式或服务商计费规则不支持；检查接口模式、模型和图生图上传格式。
- 多渠道已配置时，确认后续渠道开启“允许作为回退渠道”。
- OpenAI 兼容站点只填基础地址，不要把完整 `/v1/images/edits` 重复拼接进去。

## 图生图返回了原图

这通常是渠道回显了输入参考图，或服务端没有真正执行编辑。插件会检测结果与输入图是否相同并拒绝记录；请换用明确支持 Images edits/参考图的模型或渠道。

## 人设拍照失败但手办化成功

两者都属于图生图，但人设拍照会附带人设图、场景和更多提示词。请在渠道中开启“允许带参考图请求”，并设置带参考图模型；WebP/GIF 等素材会在上传时转换为 PNG。

## 头像获取失败

当前平台必须提供 QQ 数字账号。`bnn @机器人 提示词` 支持机器人头像，`bnn @自己 提示词` 支持发送者自己的头像；应选择客户端真实的艾特对象。指令前的 @机器人只用于唤醒，要使用它的头像请在指令后再 @一次。

插件会从原始 OneBot 消息恢复因昵称查询失败而漏掉的艾特，并校验头像下载结果、尝试备用地址。任一指定头像仍失败时，本次不会生成或扣次数；可重试，或直接发送对应头像图片。

## 显示上游错误详情

可以开启“向用户显示上游错误详情”。聊天消息会保留状态码、错误码和端点路径，但会自动隐藏域名、主机名和 API Key。

## 图片已发出却提示超时

QQ 协议端有时先返回回执超时，稍后才显示图片。插件会将已知的 QQ 发送回执超时标为“可能已送达”，保留图片缓存，不提示确定发送失败，也不会自动重复发送。遇到该状态先等待并查看聊天，避免重复生图。

明确的拒绝发送、连接错误仍记为“发送失败”，可在 Dashboard 任务中心重发。图片发送后的任务或历史记录保存异常只写入日志，不代表图片发送失败。
