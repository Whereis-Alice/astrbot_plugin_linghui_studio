# 命令与使用

## 前缀

命令前缀始终遵循当前会话的 AstrBot 唤醒词，插件不额外要求 `/` 或 `#`。下面用 `#` 举例；群聊也可以直接 @机器人，私聊默认不需要前缀。若 AstrBot 开启“私聊需要唤醒词”，私聊也遵循该设置。

配置命名空间 `绘图` 后，可用 `#绘图 bnn 一只猫`、`#绘图 预设列表`；关闭直接命令后统一使用这种写法。`<…>` 表示必填、`[…]` 表示可选，输入时不带括号。示例中的 `@用户` 请使用 QQ 的实际艾特选择。

本文列出日常指令的语法、参数和作用范围；完整管理指令及别名见[管理员命令](ADMIN_COMMANDS.md)，包括额度、渠道、预设、参考图和排障。自然语言工具参数见 [LLM 工具](LLM_TOOLS.md)。

## 绘图

| 命令 | 用法 |
| --- | --- |
| `#画` | 自定义绘图；带图片时自动图生图。别名可在配置中修改。 |
| `#bnn` | 自定义绘图；支持 `@用户` 头像参考与本次指定渠道，始终保留此入口。 |
| `#文生图` | 强制使用文生图流程。 |
| `#文生图 <预设名> [追加要求]` | 使用命名预设文生图，例如 `#文生图 GIF表情 一只眨眼的猫`。 |
| `#头像图生图` | 使用发送者自己的 QQ 头像作为参考图。 |
| `#人设拍照` | 使用已上传的人设图和场景提示词。 |
| `#预设名` | 调用预设，可在后面追加要求。 |

示例：

```text
#画 电影感城市夜景
#画 水彩风猫咪
#bnn @甲 @乙 两个人并肩站在海边
#文生图 复古海报风格
#头像图生图 穿着雨衣站在街角
#手办化
#人设拍照 图书馆窗边，下午阳光
```

`#bnn @甲 @乙 提示词` 按艾特出现顺序去重并使用头像，包括指令后的 @机器人和 @发送者自己；艾特也可穿插在提示词里。指令前用于唤醒的 @机器人不作参考图，例如 `@机器人 bnn 一只猫` 是文生图，`@机器人 bnn @机器人 肖像` 才使用机器人头像。若任一头像获取失败，本次会提示失败对象，不生成、不扣次数。若明确要求“不带名字、群名、QQ 号或 ID”，隐私限制会自动加强。

### bnn 本次指定渠道

**`#bnn 渠道m 一只猫` 会仅使用 ID 为 `m` 的渠道。** 渠道 ID 在绘图渠道页查看，填写 ID，不填显示名称或列表序号。

| 支持的语法 | 示例 |
| --- | --- |
| `#bnn 渠道<渠道ID> <提示词>` | `#bnn 渠道m 一只猫` |
| `#bnn --渠道 <渠道ID> <提示词>` | `#bnn --渠道 miku 一只蓝色小猫` |
| `#bnn --渠道=<渠道ID> <提示词>` | `#bnn --渠道=orb 雨后的街道` |
| `#bnn --channel <渠道ID> <提示词>` | `#bnn --channel m 一幅风景画` |
| `#bnn --channel=<渠道ID> <提示词>` | `#bnn --channel=miku 一只猫` |

参数必须放在提示词最前面。短写法中“渠道”和 ID 必须紧挨着，`渠道 m` 不是渠道选项；要使用空格请写 `--渠道 m`。同样适用于默认的自定义短命令 `#画`；修改自定义短命令后使用实际配置的名称。`#文生图`、`#人设拍照` 没有这组选项。

```text
#bnn 渠道m @甲 @乙 两人在海边合影
#bnn --渠道 orb @机器人 肖像
#bnn 渠道m 将附图改成水彩风
#绘图 bnn 渠道m 一只猫
```

第三例需要附图或回复图片，第四例使用命名空间 `绘图`。头像按出现顺序去重，附图与引用图片照常生效。

本次选择只影响这一条请求，不修改会话或全局配置。仍可尝试该渠道内部的模型与 Key，失败不会切换到其他渠道；不存在、禁用、额度耗尽或不接受参考图会明确报错。正常计次，仍受个人、群、总次数和渠道日额度限制。持久选择优先渠道时，管理员使用 `#通道`。

### 本次指定模型序号

`#bnn(2) 提示词`、`#画(2) 提示词`、`#手办化(2) 追加要求` 只为本次请求选择模型，也支持全角括号。序号从 1 开始，对应管理员 `#模型` 查询的渠道模型列表；先查列表再使用有效序号，越界不会切换成目标模型。预设调用仍需附图或引用图片。

```text
#bnn(2) 渠道m 一只猫
#手办化(2) 保留原来动作
```

## 预设与参考图

```text
#预设列表
#预设列表 我的
#预设列表 自带
#预设列表 改过
#预设列表 文字
#预设列表 说明
#预设列表 说明 手办
#预设查看 手办化
```

这些列表和提示词查询可供普通用户使用。预设添加/删除、预设参考图与人设参考图的管理（包括查看）需要管理员，完整用法见[预设提示词与参考图管理](ADMIN_COMMANDS.md#预设提示词)。

`我的` 包括自定义与修改过的预设，`自带` 只显示未修改的内置预设，`改过` 只显示修改项。`文字` 返回名称清单，`说明` 逐行显示用途；可组合来源、展示方式和多个名称关键词，多关键词取交集。文字与说明同时指定时，以文字为准。

列表别名为 `lm列表`、`lmlist`；查看别名为 `lm查看`、`lmv`、`lm预览`。预设可设置有序渠道和独立图片格式；需要 GIF 时选择 `gif`，仅在提示词中写“动图”不会自动切换格式。

## 人设拍照

```text
#人设场景列表
#人设拍照 咖啡店 穿浅色外套，望向窗外
#人设拍照 图书馆 自然微笑，竖构图
```

语法为 `#人设拍照 [场景] [额外要求]`。场景可填预设关键词或具体描述，需要管理员先启用人设并上传参考图。附图可补充合影对象、衣着或风格要求；人物身份优先使用人设参考图。

直接指令一次生成一张，没有 `count` 参数。多张可交给 LLM 工具，例如“给我三张你在咖啡店的照片，每张表情不同”，受工具张数上限和额度限制。`#人设场景列表` 的别名是 `场景列表`，普通用户可查询；`#人设状态` 及素材管理需要管理员。

管理员可在人设页设置“自拍渠道顺序”：首项主用，其余备用；失败只在所选范围回退，留空沿用普通参考图路由。覆盖指令、LLM、后台、多张自拍和重跑。默认内容审核拒绝会停止切换，提示会明确原因。

## 批量处理与 PDF

| 指令 | 作用 |
| --- | --- |
| `#批量<预设名> [追加要求]` | 逐张处理收集到的图片，例如 `#批量手办化 保留背景`。 |
| `#全部<预设名> [追加要求]` | 同批量处理，例如 `#全部Q版化`。 |
| `#批量处理 <预设名或提示词> [追加要求]` | 使用预设或自由提示词；也可写 `#全部处理 …`。 |
| `#打包PDF [文件名要求]` | 把当前、引用或近期上下文中的图片打包为 PDF，不生图。 |

```text
#批量手办化 保留每个人原来的动作
#全部Q版化
#批量处理 改成柔和水彩画，保留主体
#打包PDF
#打包PDF 文件名为猫咪合集.pdf
```

批量从当前、引用和近期上下文收集图片，受批量最大张数、并发、重试和失败策略约束；按图片逐张计次。不要把 LLM 工具参数如 `max_images=` 当作聊天参数。

`#打包PDF` 的别名为 `图片转PDF`、`合成PDF`，可等待当前任务的成功图片后打包。文件名支持“文件名为”“名称为”“输出为”或明确 `.pdf` 文件名；聊天指令没有用数字限制张数的解析。需要“先处理再打包”时，使用 LLM 批量工具的 PDF 输出，见 [LLM 工具](LLM_TOOLS.md)。

## 渠道与模型

以下命令的查询与切换都需要 **AstrBot 管理员**身份，QQ 群管理员身份本身不算。

```text
#通道                 查看当前会话渠道
#通道 2               切换当前会话渠道
#通道 自动            清除会话选择，跟随全局配置
#通道 全局 primary    修改全局默认渠道（管理员）
#通道 全局 自动       全局恢复渠道列表顺序
#模型 gpt-image-1     切换当前会话模型
#模型                 查看渠道模型列表与会话覆盖
#模型 2               本会话选择列表中的第二个模型
#模型 取消            恢复使用渠道默认模型
```

开启会话级选择时，切换只影响 AstrBot 当前会话，覆盖会在配置的有效期后自动恢复。关闭会话渠道选择后，渠道切换会改全局主渠道；关闭会话模型选择后，需到渠道页维护模型。模型命令不再改全局模型。通道别名为 `渠道`，模型别名为 `切换模型`。完整语法见[管理员命令](ADMIN_COMMANDS.md#绘图渠道与模型)。

| 选择方式 | 影响范围 | 失败后的行为 |
| --- | --- | --- |
| `bnn` 开头指定渠道 | 本次请求 | 只用该渠道内部的模型与 Key。 |
| 预设的渠道列表 | 该预设 | 在列表内按序回退。 |
| 自拍渠道列表 | 人设拍照 | 在列表内按序回退。 |
| `#通道 <ID>` | 当前会话 | 优先该渠道，允许普通回退。 |
| `#通道 全局 <ID>` | 全局普通路由 | 修改默认优先渠道。 |

本次指定渠道优先于预设列表，预设列表优先于自拍列表，之后使用会话与普通默认路由。预设或自拍绑定渠道时使用各渠道配置的模型，不受会话模型覆盖影响。

## 额度与帮助

```text
#签到
#额度
#帮助
#打包PDF
#人设场景列表
```

管理员增加次数可直接用：

```text
#加用户额度 123456789 10
#加用户额度 @用户 10
#加群额度 987654321 50
#统计
```

这些命令都需要管理员。个人余额在群聊与私聊之间共用；补额度不会自动授予白名单访问权。更多查询、别名和范围说明见[管理员命令](ADMIN_COMMANDS.md#用户与群额度)。名单、重置额度、成功记录和任务中心也可在 Dashboard 管理，规则见[配置指南](CONFIGURATION.md)。

`#预设列表 说明` 会一行显示每个预设的用途；追加关键词可以筛选，例如 `#预设列表 说明 手办`。当前内置预设主要是图生图预设，需要图片或引用图片。没有参考图时，请使用 `#文生图` 或无图的 `#画`。

发送 `#总次数` 可查看所有会话共享的全局总上限、累计已用和剩余次数。管理员用 `#总次数 100` 设置上限、`#增加总次数 50` 增加上限、`#总次数 不限` 关闭上限；命名空间模式可使用 `#绘图 总次数`。全局总上限耗尽后即使个人/群额度充足也无法生成。

签到别名为 `手办化签到`，额度别名为 `手办化查询次数`，帮助别名为 `手办化帮助`、`lmh`、`lm帮助`。普通用户可查询总次数；设置、增加或关闭上限需要管理员。完整管理命令已分组列在[管理员命令](ADMIN_COMMANDS.md)。
